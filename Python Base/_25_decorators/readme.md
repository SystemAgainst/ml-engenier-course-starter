# Декораторы Python — шпаргалка к собеседованию Middle+

## Коротко

Декоратор — вызываемый объект, который принимает функцию (или класс) и возвращает новый объект, обычно функцию-обёртку. Он позволяет добавить поведение до и/или после вызова, не меняя саму функцию.

```python
def my_decorator(func):
    def wrapper(*args, **kwargs):
        print("До вызова")
        result = func(*args, **kwargs)
        print("После вызова")
        return result

    return wrapper


@my_decorator
def add(a, b):
    return a + b
```

Синтаксис `@my_decorator` эквивалентен присваиванию:

```python
add = my_decorator(add)
```

Важно: при создании декорированной функции Python вызывает сам декоратор, но обычно не вызывает обёрнутую функцию. Вызов `func(...)` происходит позже, когда вызывают декорированное имя.

## Что такое `*args` и `**kwargs`

- `*args` собирает дополнительные позиционные аргументы в кортеж (`tuple`).
- `**kwargs` собирает дополнительные именованные аргументы в словарь (`dict`).

```python
def show_args(*args, **kwargs):
    print(args)
    print(kwargs)


show_args(10, "x", city="London", active=True)
# args == (10, "x")
# kwargs == {"city": "London", "active": True}
```

В обёртках их обычно используют, чтобы принять аргументы вызова и передать их исходной функции без изменений:

```python
def wrapper(*args, **kwargs):
    return func(*args, **kwargs)
```

Звёздочки имеют и другое применение при вызове: `func(*items)` распаковывает итерируемый объект в позиционные аргументы, а `func(**options)` — словарь в именованные аргументы.

Одинарная `*` в объявлении функции задаёт границу keyword-only параметров:

```python
def get_weather(*, city, date):
    ...


get_weather(city="London", date="2026-10-14")  # корректно
# get_weather("London", "2026-10-14")          # TypeError
```

`*args` и `**kwargs` — это обычные имена параметров; специальное значение имеют звёздочки. Их можно назвать иначе, но принято использовать именно эти имена.

## Что важно в реализации декоратора

1. **Возвращать обёртку, а не вызывать её при декорировании.**

   Правильно: `return wrapper`.

   Ошибка: `return wrapper()`. Тогда обёртка запускается сразу при импорте/создании функции, часто без необходимых аргументов.

2. **Передавать исходные аргументы:** `func(*args, **kwargs)`.

3. **Возвращать результат исходной функции.** Без `return result` декорированная функция вернёт `None`, даже если исходная возвращала значение.

4. **Сохранять метаданные с помощью `functools.wraps`.** Без него имя, docstring и другие метаданные декорированной функции будут принадлежать `wrapper`.

```python
from functools import wraps


def my_decorator(func):
    @wraps(func)
    def wrapper(*args, **kwargs):
        return func(*args, **kwargs)

    return wrapper
```

5. **Осознанно обрабатывать исключения.** Если обёртка перехватывает исключение, нужно решить: повторить попытку, преобразовать ошибку или пробросить её дальше. Не следует молча скрывать ошибку.

## Декоратор с параметрами

Декоратор с настройками — это функция, которая возвращает собственно декоратор. Поэтому появляется ещё один уровень вложенности:

```python
def repeat(times):
    def decorator(func):
        @wraps(func)
        def wrapper(*args, **kwargs):
            result = None
            for _ in range(times):
                result = func(*args, **kwargs)
            return result

        return wrapper

    return decorator


@repeat(3)
def greet(name):
    print(f"Hello, {name}")
```

Порядок вызовов: `repeat(3)` → `decorator(func)` → позднее `wrapper(...)`.

## Типизация обёртки

Для типизированного декоратора, который сохраняет связь между параметрами/типом результата исходной функции и обёртки, в современных версиях Python можно использовать `ParamSpec` и `TypeVar`:

```python
from collections.abc import Callable
from functools import wraps
from typing import ParamSpec, TypeVar

P = ParamSpec("P")
R = TypeVar("R")


def logged(func: Callable[P, R]) -> Callable[P, R]:
    @wraps(func)
    def wrapper(*args: P.args, **kwargs: P.kwargs) -> R:
        print(f"Вызов {func.__name__}")
        return func(*args, **kwargs)

    return wrapper
```

### `.env` и переменные окружения

Файл `.env` — простой текстовый файл для локальных переменных окружения, например API-ключей и настроек приложения. Он помогает не хранить секреты прямо в исходном коде и удобно задавать разные значения для разных окружений.

Пример `.env` в корне проекта:

```dotenv
API_KEY=ваш_личный_api_ключ
```

Python сам по себе не загружает `.env`. Для этого примера используется библиотека **`python-dotenv`**. Установить её можно из терминала в активном окружении проекта:

```bash
python -m pip install python-dotenv
```

Загружают значения в окружение процесса так:

```python
import os
from dotenv import load_dotenv

load_dotenv()

api_key = os.getenv("API_KEY")
if not api_key:
    raise RuntimeError("Переменная API_KEY не задана")
```

`load_dotenv()` обычно ищет `.env` в текущем каталоге и родительских каталогах. `os.getenv("API_KEY")` вернёт строку со значением или `None`, если переменная не задана. В примере урока ключ читается при загрузке модуля через `API_KEY = os.getenv("API_KEY")`, а затем добавляется к URL запроса.

**Безопасность и практика:**

- Добавьте `.env` в `.gitignore` и не коммитьте его: в нём могут быть секреты. Если ключ уже попал в репозиторий, удаление файла не делает его безопасным — ключ нужно отозвать или заменить.
- Добавьте в репозиторий `.env.example` с названиями переменных и безопасными примерами/пустыми значениями, но без настоящих ключей.
- В продакшене секреты обычно передают через переменные окружения или secret manager платформы; `.env` — удобное локальное решение, а не хранилище секретов для публикации.
- Не выводите ключ в логи и сообщения об ошибках.
- Проверяйте обязательные настройки явно, прежде чем выполнять запрос; отсутствие ключа не должно маскироваться под обычную сетевую ошибку.

При реализации retry-механизма на собеседовании стоит обсудить:

- какие именно ошибки повторять, а какие сразу пробрасывать;
- ограничение числа попыток и задержку (например, exponential backoff);
- нужен ли jitter, чтобы множество клиентов не повторяло запрос одновременно;
- timeout для сетевого запроса;
- идемпотентность операции: безопасно ли повторять запрос;
- что происходит при исчерпании попыток;
- не превращает ли обёртка успешный результат в `None`;
- сохраняются ли сигнатура и метаданные (`@wraps`).

В текущем примере `requests.get` вызывается без `timeout`, а `response.json()` сам по себе не проверяет HTTP-статус. Для надёжного клиента обычно задают timeout и вызывают `response.raise_for_status()`. Повторять следует только согласованный набор временных ошибок; невалидный ответ или постоянную ошибку сервера не стоит автоматически считать успешным результатом.

## Порядок нескольких декораторов

```python
@first
@second
def task():
    ...
```

Эквивалентно:

```python
task = first(second(task))
```

Декораторы применяются снизу вверх при создании функции. При вызове порядок входа в обёртки будет зависеть от вложенности: сначала внешний `first`, затем внутренний `second`; выход — в обратном порядке.
