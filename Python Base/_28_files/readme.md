# Урок: относительные пути и работа с файлами

## Почему возник `FileNotFoundError`

При запуске команды:

```bash
poetry run python _28_files/files_json.py
```

текущая рабочая директория — `Python Base`. Относительный путь:

```python
open("files/data.json", "w")
```

считается относительно рабочей директории процесса, а не папки, в которой лежит `files_json.py`. Поэтому Python ищет файл по пути `Python Base/files/data.json`. В этом проекте папка находится по пути `Python Base/_28_files/files/`, поэтому искомый путь не совпадает.

Режим `"w"` создаёт файл, если его ещё нет, но **не создаёт отсутствующие родительские папки**. Если каталога `files` по вычисленному пути нет, будет `FileNotFoundError`.

## Надёжный способ: строить путь от скрипта

`Path(__file__).resolve().parent` указывает на папку, где находится сам Python-файл. Добавив к ней `files/data.json`, получим путь, не зависящий от того, из какой директории запущена команда:

```python
import json
from pathlib import Path

data = {"name": "Mike", "age": 30, "city": "New York"}

data_dir = Path(__file__).resolve().parent / "files"
data_dir.mkdir(parents=True, exist_ok=True)
data_path = data_dir / "data.json"

with data_path.open("w", encoding="utf-8") as file:
    json.dump(data, file, indent=4)

with data_path.open("r", encoding="utf-8") as file:
    loaded_data = json.load(file)

print(loaded_data)
```

`mkdir(parents=True, exist_ok=True)` создаёт каталог, если его нет, и не выдаёт ошибку, если он уже существует. Если каталог гарантированно есть в проекте, эту строку можно опустить.

## Другие способы и когда они подходят

- Можно запускать скрипт из папки `_28_files` и использовать `"files/data.json"`. Тогда путь будет считаться относительно `_28_files`. Но результат зависит от того, откуда запустили команду.
- Можно явно задавать абсолютный путь, но такой код часто привязан к конкретному компьютеру и неудобен для переноса проекта.
- Для путей внутри проекта обычно удобно использовать `pathlib` и строить их от `__file__`.

## Закрытие файлов

Конструкция `with` автоматически закрывает файл, даже если во время чтения или записи возникло исключение. Вызов `file.close()` вручную легко забыть. Незакрытые файлы удерживают системные ресурсы (например, файловые дескрипторы) и могут не сразу сбросить буфер записи; при большом числе таких файлов программа может исчерпать доступные дескрипторы. Это обычно точнее называть утечкой ресурсов, а не утечкой памяти.

### Что такое утечка памяти

Утечка памяти — ситуация, когда программа продолжает удерживать объекты в памяти, хотя они больше не нужны, поэтому Python не может освободить их. В Python память обычно освобождается автоматически, когда на объект больше нет ссылок, но ссылка, оставшаяся в списке, словаре, кэше или глобальной переменной, не даёт объекту исчезнуть.

Популярный пример — бесконечно накапливать данные в списке:

```python
processed_messages = []

def handle_message(message):
    processed_messages.append(message)
```

Если `handle_message` вызывается постоянно, список растёт и хранит все сообщения, даже если приложению нужны только последние. Исправление зависит от задачи: не сохранять ненужные данные, ограничить размер коллекции или очищать её, когда данные больше не нужны.

**Как это проявляется:** процесс постепенно потребляет всё больше оперативной памяти. Это можно заметить в Диспетчере задач / Activity Monitor или системных метриках; сервис может замедлиться, получить `MemoryError` либо быть принудительно завершён операционной системой из-за нехватки памяти. Утечка часто заметна не по одной операции, а по устойчивому росту потребления во времени.

Незакрытый файл сам по себе обычно не является примером утечки памяти в строгом смысле. Это утечка ресурса: остаются занятыми файловые дескрипторы и связанные ресурсы ОС. Если открывать много файлов и не закрывать их, программа может получить ошибку `Too many open files`; при записи также важно корректно закрыть файл, чтобы сбросились буферизованные данные. Используй `with open(...) as file:` — блок гарантирует закрытие файла после завершения работы с ним, в том числе при исключении.

## Итоги урока: JSON, CSV и менеджеры контекста

### Что такое менеджер контекста

Менеджер контекста — объект, который подготавливает ресурс для работы и гарантированно выполняет завершающие действия после неё. В Python его используют с конструкцией `with`.

```python
with open("data.json", "r", encoding="utf-8") as file:
    data = json.load(file)
```

При входе в блок файл открывается, а при выходе закрывается автоматически — в том числе, если внутри блока возникло исключение. Поэтому `with` надёжнее, чем отдельные вызовы `open()` и `close()`: не нужно помнить о закрытии во всех ветках кода.

У менеджера контекста есть методы `__enter__()` и `__exit__()`: первый подготавливает ресурс и возвращает значение для переменной после `as`, второй выполняет очистку. Для собственных менеджеров контекста можно определить эти методы или воспользоваться `contextlib`.

### Чему я научился в примерах

- Открывать файлы для записи, чтения и добавления данных; выбирать режимы `"w"`, `"r"` и `"a"`.
- Записывать Python-данные в JSON через `json.dump()` и читать их обратно через `json.load()`.
- Записывать строки в CSV с помощью `csv.writer` и `writerows()`.
- Читать CSV как словарь через `csv.DictReader`, обращаясь к значениям по названиям столбцов.
- Записывать словари в CSV через `csv.DictWriter` и `writerows()`.
- Использовать `with open(...)` для автоматического и надёжного закрытия файлов.
- Учитывать рабочую директорию при указании относительного пути к файлу.

При работе с `DictWriter` названия в `fieldnames` должны совпадать с ключами словарей. В примере `_28_files/files_csv.py` написано `'occup ation'` с пробелом, тогда как данные используют `'occupation'`; это несоответствие нужно исправить, иначе столбец будет записан некорректно.

Также путь `'persons.csv'` в `context_manager.py` считается относительно текущей рабочей директории. Запускай пример из каталога, где лежит этот CSV-файл, или сформируй путь от `__file__`, как описано выше.

## Короткий чек-лист

1. Уточнить, откуда запускается программа (текущую рабочую директорию).
2. Помнить: относительный путь считается от неё, а не автоматически от файла скрипта.
3. Проверить, существуют ли все родительские папки: `open(..., "w")` не создаёт каталоги.
4. Для устойчивых путей внутри проекта строить путь от `Path(__file__).resolve().parent`.
5. Открывать файлы через `with`, указывать кодировку для текстовых файлов.
